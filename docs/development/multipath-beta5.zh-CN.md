# Multipath beta5：连接级字节流

状态：已在独立的 `multipath-beta5` 开发分支中实现，尚未发布。验证结果与仍未通过的测试见[开发验证记录](multipath-beta5-validation.zh-CN.md)。

## 参考基线

协议以 RFC 8684 为基线，包含已验证的勘误 6609。RFC 6182 提供架构层面的职责划分，RFC 6356 描述耦合拥塞控制，RFC 6897 规定面向应用的字节流语义。

实现参考 Linux 提交 `587858367581b9c55c3690f4e63382ad622719d4`，重点包括 `net/mptcp/protocol.c`、`options.c`、`subflow.c`、`pm.c` 和 `sched.c`。本项目重新实现其中适用的机制，不直接引入 Linux 源代码。

相关机制并不只是一个固定比例调度器：

| MPTCP 机制 | 在本项目的可靠字节流聚合层中的对应方式 |
| --- | --- |
| MP_CAPABLE、密钥、初始数据序号 | 由带版本号的主路径 hello 创建连接，不与旧版 multipath 协议协商兼容。 |
| MP_JOIN、token、nonce、HMAC | 辅助传输路径加入已有连接；每次路径建立都有独立于逻辑连接状态的实例标识。仅凭会话标识加入的机制，不等同于 MPTCP 带认证的 MP_JOIN。 |
| DSS 映射 | 每段载荷将路径字节流中的一个范围映射到逻辑字节流中的不可变范围。重注入改变路径映射，不改变逻辑数据序号。 |
| Data ACK | 对已连续收到的字节前缀进行累计、单调确认。它独立于应用读取进度，也独立于各路径的接收回执。 |
| Subflow ACK | 通过显式的对端反馈，测量数据经过整条 child 路径的交付进度。本地 `Write` 成功，或代理本地 TCP 跳的 `TCP_INFO`，都不代表端到端接收确认。 |
| 连接级接收窗口 | 两条路径共享一个按字节寻址的窗口，已通告的窗口右边界不会后退。应用消费数据后，可用窗口向前推进。 |
| 发送／重传队列 | 两条路径共用一个连接级队列。在 Data ACK 确认之前，以及任何传输 writer 仍持有引用期间，相关数据都必须保留。 |
| 乱序接收队列 | 按字节范围处理乱序、重复和重叠。Data ACK 将数据保管责任转移给接收端；已经确认但尚未被应用读取的字节，不能再被驱逐。 |
| 接收内存压力 | 先停止扩大窗口。Linux 可以裁剪尚未确认的乱序数据，但不能丢弃已确认的应用数据。移植时必须保留这一区别，并为接收头部的推进预留资源。 |
| Linux 默认发送调度器 | 根据待交付的数据量与观测到的路径服务速率，选择可用路径。不能把手动比例或本地 socket 队列是否为空，当成交付能力估计。 |
| 重注入与停滞路径 | 在可用路径上补发连接中最早未确认的数据。路径暂时停滞不等于逻辑连接失败，也不必因此关闭并重连。 |
| DATA_FIN | 按序占用一个逻辑字节序号的事件。单条路径的 EOF 不等于逻辑字节流的 EOF，读方向和写方向的关闭仍相互独立。 |
| MP_FASTCLOSE、MP_TCPRST | 区分逻辑连接中止与单条传输路径失败。不能仅凭单路径的终止事件就认定整个逻辑流已经结束。 |
| ADD_ADDR、REMOVE_ADDR、MP_PRIO | 使用已配置的 child outbound 代替地址发现。分方向的激活策略以及主路径／booster 策略，与数据交付正确性分离。 |
| MP_FAIL、DSS 校验和、无限映射 | 本分帧协议不处理中间盒改写，也不回退到旧式 TCP。TCP／QUIC 已提供传输完整性保障；非法映射仍作为协议错误处理。 |
| LIA／耦合拥塞控制 | 不在已经可靠的 child 字节流之上再叠加 RFC 6356。该机制需要的报文 ACK、丢包、cwnd、MSS 等输入，在本层不可直接获得。拥塞控制仍由 child TCP／QUIC 承担，包括 Brutal。 |
| TCP Fast Open | 保留现有的延迟 hello 与首段载荷合并写入机制。内核 MPTCP 对 SYN 载荷的特殊处理，不意味着本聚合层的早期数据应被排除在逻辑序号空间之外。 |

Linux 当前默认发送路径使用 `sk_wmem_queued / avg_pacing_rate`，同时结合有界发送突发和共享窗口的可发送条件。这里的排队内存包含尚未被 TCP 确认的数据。其重注入路径还会考虑传输进度以及空闲、可用的替代路径。这两套机制都不等同于用本地 Go channel 长度除以 `bandwidth_mbps`。

## 替换边界

替换聚合数据状态、按帧索引的流控 epoch，以及仅服务于 leg1 的 replay 映射表。新旧状态机不并行运行。

保留 child 拨号、UDP 转发、对外的 `net.Conn` 行为、TFO、分方向激活策略、状态发布和共享内存预算服务。适配层应报告新状态，不继续沿用过时计数器。

从运行时调度和状态中移除 `bandwidth_mbps`。在 beta5 中，它既不充当速率上限，也不充当初始速率估计。为便于迁移，解析器接受这一旧字段，但忽略其值，并在每个节点初始化时打印警告。其他未知字段仍会被拒绝，旧版线协议仍不受支持。

## 状态与数据所有权

连接级状态包括 `snd_una`、`snd_nxt`、`peer_window_end`、`rcv_nxt`、`read_next`、本端与对端 DATA_FIN，以及发送和接收存储。每条路径独立维护实例标识、发送与接收字节边界、交付测量和传输生命周期。

网络写入、向应用交付数据以及等待内存期间，都不持有连接状态锁。

以下事件必须区分：

1. 应用 `Write` 的数据被接收到有界逻辑发送存储中。
2. child `Write` 接收了一段映射。这不代表数据已交付。
3. 对端报告路径接收回执。它更新路径进度，不更新 `snd_una`。
4. 对端 Data ACK 推进 `snd_una`。当仍在使用这些字节的 writer 引用也已释放时，发送存储才能释放被确认的数据。
5. 接收端应用读取字节。此时，相应接收存储才可复用，接收窗口才允许向前滑动。

迟到的重复数据不能修改已接收的字节。旧路径实例的重连事件和反馈，不能确认或判定新路径失败。窗口更新、重复反馈和乱序控制消息，都不能让累计确认位置或窗口右边界后退。超出已发送范围的确认会被拒绝。

运行时在可靠 child 交付 DATA 前缀后就处理这些字节，不等待整段最大尺寸映射全部到齐。序号溢出会在交付前被拒绝。辅助路径在一个映射传到一半时失败，不会使已经接收的前缀失效；重注入可以重复包含该前缀，但不会向应用交付重复数据。

## 调度与恢复

调度依据对端观测到的路径交付进度，而不是 child 缓冲区接受了多少数据。初始估计由内部提供，并由实测值替换，不保留手动带宽比例。

启动采样必须充分利用可用传输能力，不能在预热 leg1 时让 leg0 无法推进。停止取得交付进展的路径不再接收新任务，逻辑流和另一条路径仍保持可用。

重注入始终引用已有的连接数据，不依赖新应用数据的分配。在接收窗口已满或内存达到高水位时，重注入仍必须能够进行。它不产生新的逻辑字节，也不能撤回已经排入 TCP／QUIC 的数据。重注入的重复字节计入传输流量，但不计为新的应用流量。

带内控制帧不能越过已经排入可靠 child 字节流的数据。writer 优先级只能调整尚未提交给 child 的数据顺序。这与通过 TCP option 携带 ACK 有根本区别，必须在超时估计和全双工测试中体现，不能宣称控制消息走带外通道来掩盖这一限制。同样，本聚合层不能直接观测底层链路的报文丢包率。

## 必需的验证

纯状态测试必须覆盖任意字节分片、重叠、重复重注入、反馈乱序、部分 ACK、FIN 先于缺失数据到达、半关闭、旧路径实例反馈、满窗口恢复，以及内存压力下的推进能力。模型测试应把实际接收字节和 EOF 与正确的有序字节流模型对照，包括任一路径或两条路径同时停滞、应用反压等情况。

集成测试保留所有 direct／代理及父子 TFO 组合，并覆盖短请求、服务端先发数据的协议、取消和 deadline 行为。leg1 失败不能对仍存活的主路径连接伪造 EOF 或 reset。

性能验收在 nec 的隔离环境中使用真实 TCP／HY2 传输，覆盖 60／120 ms RTT 不对称、独立施加的 20% UDP 丢包、大 QUIC 窗口、单流和并发下载、上传，以及接收应用阻塞。

应对照同轮测试中的单 leg0、单 HY2 和 beta4 基线，报告启动表现与持续应用有效吞吐。仅通过合成队列测试，不能证明能够跑满链路。任何协议都无法无条件保证每个时刻都优于最快的单独路径。
